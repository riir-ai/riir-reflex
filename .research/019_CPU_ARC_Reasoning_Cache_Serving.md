## TL;DR

CPU-ARC decouples task-SOLVING from task-EXECUTION: a builder model decomposes a frontier model's reasoning transcript into **semantic functions** — code units whose inputs, outputs and callees are referenced by natural-language descriptions and resolved at runtime by embedding search — parameterizes them over the problem class (generic input template + per-parameter validity ranges), certifies them against rephrasings and re-parameterizations with unanimous judge committees, compiles the matured network to a standalone artifact (static resolution of every dynamic dispatch), and serves new queries with deterministic CPU execution plus a 1B-class model at extraction seams, **falling through to the source model on cache miss**. Measured: cache accuracy ≥ source on 7/8 hard math/science benchmarks (AIME: the cache BEATS its own source — deterministic execution avoids the stochastic arithmetic slips), ≥90% perturbation robustness, 16–291× cheaper per invocation. ⚠ Every accuracy/robustness/cost figure in this note is **NVIDIA's number on NVIDIA's benchmark corpus**; nothing here imports their bars — our gates register our own thresholds on our own corpora.

**Distilled for the decision-serving family (modelless):** the mechanism is a NEW LANE CLASS on the escalating ladder — a cheap tier of compiled, certified, parameterized cached reasoning sitting below the corpus-scored lane, abstaining into the think leg on extraction failure or entry-point miss. The paper's own Figure 1 (`try cache.use(request); except → llm(request)`) IS the ESC shape. What makes it ours: construction can ride the stack's own captured traces (ESC cal/test triples, hosted_expert calls, fix trajectories), the extraction seams can be TYPED PARSERS where domains are closed (zero-LM — stronger than their small-model seams), deployment rides the vessel/manifest laws (signed, monotonic hot-swap — their "compiled cache" has no authenticity story), and the verify ladder's compile gate is a strictly stronger oracle than their judge committees.

## 1. What it does (mechanism + their measured claims)

**Semantic function** = `f: Context → dict[str, Any]`; everything referenced by NL description + examples, never by identifier. Runtime primitives: `load` (vector-similarity retrieval over layered context memory), `do` (discover + invoke a semantic function by description; pushes an isolated memory layer), `narrate` (reasoning-step record → the explanation trace), `lm` (target-model call for elementary NLP: classification/summarization), `extract` (verbatim value extraction + type coercion), `convert`/`smart_convert` (programmatic then LM-assisted coercion via `ast.literal_eval`), `invoke_tool`.

**Construction** (builder ℬ = frontier model, per transcript): (1) input–output isolation; (2) decomposition into hierarchical logical ops at function granularity, reusable sub-computations marked for standalone extraction; (3) parameter recognition — generic input template `q(●1..●n)`, concrete values, **logical validity ranges**; (4) planning — function list, dependency order (bottom-up), granularity dial (fine/medium/coarse); (5) implementation — agentic loop: candidate → registry equivalence search → write with primitives → **static checks** (syntax + narration-quality: narrate()-call count commensurate with control-flow complexity) → dispatch test vs transcript fragment (judge) → e2e correctness (judge vs transcript + golden) → **extraction-robustness round trip ×N** (target model extracts params from raw input, root dispatched with extracted params, judged).

**Invocation:** entry-point cosine search (template + original input both registered) → threshold else MISS → source model; extractor-LM parameter extraction; dispatch; output dict + narration trace. **Compilation:** once the registry matures, `do()` → direct calls, `load()` → dict lookups → standalone module, no embedding engine; `lm()`/`extract()` survive (they need the small model).

**Target model:** frontier smalls sufficed (Haiku 4.5 / Gemini 3.0 Flash Lite / GPT 5.4 Nano); then a **finetuned Llama 3.2 1B** sufficed (§D: role-typed invocation logs → 20% harvest, executor roles only → 10× payload-only synthetic augmentation → SFT, early-stop patience 3). The training half is Plan 510's subject.

**Their measured claims** (retail API pricing, Mar 2026; all self-reported — we re-ran nothing):

| Axis | Result |
|---|---|
| Cache vs source accuracy | ≥ source on 7/8 (AIME '25: 93.3 vs 83.3; AIME '26: 96.7 vs 90.0; GSM8K the lone deficit, 98.0 vs 98.5) |
| Fidelity to transcript | >98% on 6/8; 100% MMLU-Pro |
| Perturbation robustness | ≥90% every benchmark × mode (phrasal / parametric / combined); lowest 90.8% (AIME '26 combined) |
| Cost | 16–291× savings per invocation; builder 12–84× source; invocation $0.0004–0.0019/sample |
| Break-even | N* = B/(S−C): ~13 invocations (AIME) … ~90 (GSM8K) |
| Robustness testing | generator = source model; unanimous 2-judge committees; parametric mode criterion (iv) = **calibration check**: if the generator cannot re-derive the ORIGINAL known answer, the perturbation measures the generator, not the cache — discard |

**Perturbation taxonomy** — phrasal (equiparametric: rewording, parameters fixed), parametric (equiphrasal: new parameters, phrasing fixed), combined (equisubstantive: both) — applied only to cache-correct problems, judged against golden (phrasal) or the validated final narration's answer (parametric).

## 4. Cousins + signal-diffs (§3.6 discipline)

- **reflex Research 016 (XERJ Query-1)** — nearest cousin. Signal consumed: per-query program EMISSION by a small trained reader over a NUMBERED TYPED-FACT listing, executor-checked, decline-first. CPU-ARC consumes a captured reasoning TRANSCRIPT and emits a built-once parameterized PROGRAM CACHE; no typed-fact store, no per-query emission, parametric generalization + certification instead of an executor's type checks. 016's row-6 re-open trigger ("any typed-fact/structured-QA lane in the family") is NOT fired by a T1 ARC lane (different grounding class). Shared lesson adopted: decline-first + the trace as the product.
- **reflex Research 004 (PAW / compile-by-training)** — NL SPEC → tiny NEURAL function (server-side LoRA compile, .paw artifact, KV-prefix persistence). CPU-ARC: reasoning TRACE → SYMBOLIC code (builder-LLM extraction, no gradient), artifact = executable logic; PAW always answers free-text, ARC abstains/misses to the source. The compile-once/serve-many posture is shared; the substrate (weights vs code) and the trust story (hash-check vs signature+monotonic-apply) differ.
- **The rulewright (riir-refine codegram)** — corpus = pattern+fix-template productions mined from MECHANICAL diagnostics (clippy/dock outputs); drafter matches spans; L2–L4 verify ladder with the compile oracle. CPU-ARC mines FREE-FORM reasoning traces with parameter recognition and validity ranges; its judge committees are a WEAKER oracle than our compile gate (which consults ground truth). Fusion already filed: Plan 510 P1 aims the §D data engine at the rulewright's own L4 seam.
- **The gram family (riir-grams + glossary)** — topogrammar acts EXTRACT topology+grammar+vocabulary but the artifacts are AUTHORED (the artifact is the truth; reflex-016's redirect line). CPU-ARC + XERJ Reader-1 are the EXTRACTED class (every artifact quotes its source). ARC is the second extracted instance in the landscape and the first whose grounding is a reasoning trace rather than a document.
- **ESC ladder (instinct grammar / reflex modelless floor / rethink enforcement)** — the gated-use shape (`cache → miss → source`) is the ladder's exact posture; a T1 lane would mount on the open seam (LaneBackend/Ext seat precedent) with enforcement+economics remaining rethink-side pointers (not in this note).
- **ReasonCache (2602.02366)** — built reasoning caches as soft-prompt PREFIX TUNING bound to a large model; gradient-built, weights-carried. ARC: discrete parameterized code, no gradient, CPU-executable, model-agnostic seams. Different substrate entirely.
- **Semantic-cache family (GPTCache, vCache, provider prefix caching)** — retrieve-and-replay a stored OUTPUT per similar query (monolithic); no decomposition, no parameters, no execution. ARC is a function library, not a memoization table. Their threshold-guarantee work (vCache) is the entry-point router's published genus — our per-suite τ + conformal floor discipline covers it.
